01 / INGEST

Validate before embedding

Run a versioned Kubernetes Job to read CSV, check required columns and encodings, normalize fields, reject malformed rows, and preserve stable record IDs.

02 / GPU BATCH

Batch embeddings on DGX

Schedule the encoder workload on GPU-capable nodes. Batch rows, record model and preprocessing versions, and publish the resulting index as an immutable artifact.

03 / ONLINE

Keep retrieval close to API

Serve the FastAPI endpoint behind internal Kubernetes Services. Load a matching FAISS index and metadata snapshot; swap versions atomically during re-indexing.

04 / OPERATE

Measure every boundary

Track ingest rejects, index age, retrieval quality, GPU utilization, queue time, p95 latency, and citation faithfulness—not just generated answer fluency.

Example query contract

POST /query
{
  "query": "Which books cover analytics?",
  "top_k": 4,
  "filters": { "collection": "catalog-v3" }
}

200 OK
{
  "answer": "…",
  "sources": [
    { "record_id": "BK-018", "title": "…", "distance": 0.82 }
  ],
  "index_version": "catalog-v3"
}

Illustrative contract only. For L2 search, a lower distance indicates a closer vector; it is not a probability. Validate filters, enforce caller authorization, and return source IDs for provenance.

Production readiness checks

  • Pin container images, model revisions, preprocessing code, CSV schema, and index version together.
  • Use GPU-aware scheduling and verify device plugin / GPU Operator configuration for the target cluster.
  • Add startup, readiness, and liveness probes; bound request and model timeouts; set resource requests and limits.
  • Protect the API with authentication, authorization, TLS, rate limits, and audit-safe logging.
  • Keep model credentials and private data out of images, logs, browser code, and Git.

Evaluate separately: Recall@k / MRR for retrieval; faithfulness and citation correctness for generation; throughput and p95/p99 latency for serving.
